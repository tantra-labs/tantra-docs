# 0004 — "Generated" API reference is hand-committed with a bogus crate path and no regeneration step

**Status**: open
**Filed**: 2026-11-23 — workspace design review (root plan 0021) · **Kind**: design-flaw · **Severity**: medium
**Plan**: [0006](../plans/0006-design-review-2026-11.md)

## What's stubbed or hardcoded

A page claiming to be generated is committed by hand and cites a mangled crate path and a non-existent command.

- `docs/api/api-reference.md:3,8-9` says "Generated by tantra-ffi-codegen ... regenerate with `make docs`" and references `crates/tantra-marketssages/src/endpoints.rs`, which is not a crate.
- The same bogus name appears at `docs/contributing/dependency_rules.md:16` and `docs/contributing/development_setup.md:63`.
- Root `Makefile:132` `docs` builds mkdocs only; nothing regenerates the page. `docs/api/rest.md:39,220` documents `tantra schema export --docs DIR` as the real generator.
- `docs/api/api-reference.md:5-6` states wire schema `4`, API `1.0.0`, while `tantra-ffi/schema/openapi.json:7883` reports `"version": "v1"`.

## Why

Readers trust a page that says it cannot drift but has no automated refresh. An operator copying endpoints misses `/api/v2` changes.

## How to close it

1. Add a `make api-docs` step calling `tantra schema export --docs docs/api`, and a CI job that fails on `git diff --exit-code` after regeneration.
2. Correct the crate name at the three locations above.
3. Render the OpenAPI document through a plugin (for example `mkdocs-swagger-ui-tag` or redoc) from `openapi.v2.json` instead of prose.
4. Align the version strings with the schema the runtime actually serves.

**Verification**: regenerate on a clean checkout and confirm an empty diff; `mkdocs build --strict`.
